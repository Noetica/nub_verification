Q2: Fix test isolation (stop the cascade) Split per-report sessions

Action: Split the DataDrivenReports_AcceptInputsAndRender test so each report gets its own browser context and login session, instead of one shared session across all 12 reports.

Why: One TOTP login (30-second window) is shared, so a failure at report N leaves the browser stuck on that report's page, cascading through reports N+1 to N+12. Daily Outbound Interval passes but Data Import fails, and the cascade masks whether the remaining 10 reports would pass on their own.

Cost: ~9 seconds of login time per report (12 logins instead of 1). Acceptable for verification quality.

How: Refactor to one xUnit test class per report, each with its own IClassFixture for the browser context. Or use a data-driven test with [Theory] + Memoization.IClassFixture per row.

Q5: Should Sandra & Kim use GrokBot?

Recommendation: No, not as the primary tool. Use nub_verification + Claude Code instead.

GrokBot could help:

  • Message from phone: Sandra/Kim could trigger tests by texting a Bot
  • Persistent sessions: browser login stays alive between runs
  • Coordination: one Bot for browser tests, another for TEFT calls

But the drawbacks outweigh this:

  • External to Noetica: tests run on Cursor's cloud, evidence lives there too
  • Per-seat cost: requires paid Cursor plans (not Noetica-paid)
  • Data residency: test conversations and evidence are in Cursor's cloud
  • Learning curve: Sandra/Kim are non-technical
  • No integration with Jira, Key Vault, or Noetica SSO

Better path: The nub_verification harness already gives Sandra/Kim the "plain English to tests" workflow via /test ENG-nnn and the scenario skill. They type what they want in a Claude chat, and Claude runs the E2E suite. No extra cost, no external data, no new tool to learn. The Telephony Testing VM is already accessible over the internet, so the Bot doesn't add remote access capability.

If remote phone access is critical: consider GrokBot as a secondary layer later, once the core harness is proven.
